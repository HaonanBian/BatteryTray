# BatteryTray 2.0.1

两个新报的问题：2.4G 连上以后界面还写着蓝牙、更新完弹出
`Failed to load Python DLL`。第二个已经找到确切的来路了。

## 一、2.4G 连接后仍显示蓝牙（已修）

一只鼠标同时有接收器和蓝牙配对时，两边都能读到它，而两边的名字不一样：

```
ASUS 驱动：ROG Keris Wireless Aimpoint（2.4G）
Windows ：ROG KERIS WIRELESS AIMPOINT
```

去重以前只判断「名字互相包含」，这两行谁都不包含谁，于是同一只鼠标会出现
两行；如果 2.4G 那半边没读到，就只剩蓝牙那一行，看起来就是「插着接收器却在
用蓝牙」。现在按**去掉括号里连接提示后的型号名**判定同一设备，并且专用 HID
驱动（2.4G）先读、优先保留，所以能读到 2.4G 就显示 2.4G。

还有一半是报告看不出原因：ASUS 驱动读不到电量时是静默跳过，报告里只写着
「0 个设备」，分不清是没插接收器、鼠标在睡觉，还是鼠标其实还连着蓝牙。
现在：

- 第 1 段驱动列表加上了 `asus`
- 新增第 3 段「ASUS 鼠标控制接口」：列出每个控制接口，以及这次读到的结果
  —— `打不开（…）` / `读不到电量（…）` / `电量报 0，鼠标可能在睡觉` / `电量=N`

换到 2.0.1 后，如果 2.4G 下还显示蓝牙，把新报告发来，这一段会直接说明是
「接收器在、鼠标没回应」还是「鼠标仍然连在蓝牙上」。

## 二、更新后弹 `Failed to load Python DLL`（已修）

```
Failed to load Python DLL
'C:\Users\...\AppData\Local\Temp\_MEI0000800c2\python313.dll'.
LoadLibrary: 找不到指定的模块。
```

程序是 PyInstaller 打成单文件的，启动时先把自己解包到
`%TEMP%\_MEIxxxxxx`，再把这个目录通过环境变量（`_PYI_APPLICATION_HOME_DIR`、
`_PYI_ARCHIVE_FILE` 等）告诉子进程。更新时，替换脚本是从**正在运行的旧副本**
里启动的，于是把这些变量一并继承下来；脚本再启动新副本，新副本看到变量就
认定「已经解包好了」，跳过解包 —— 可那个目录属于旧副本，旧副本退出时已经删掉
了，于是加载 `python313.dll` 失败。

现在启动替换脚本前就把这些变量从环境里清掉（`update.clean_environment()`），
`launch.bat` 里再逐个 `set "名字="` 兜底，两层都做了。程序本身并没有坏：弹框
之后从快捷方式再启动一次就能用，这也是「不影响用」的原因。

**注意**：从 2.0.0 更新到 2.0.1 这一趟仍然跑的是 2.0.0 的更新代码，所以还会
弹一次那个框；点「确定」后从开始菜单 / 桌面图标再打开即可。从 2.0.1 往后
的更新不会再出现。

## 验证

`verify_all.py` **288 项通过**，本轮新增 4 项：

- 启动器必须在 `start` 之前清掉 bootloader 的每一个变量
- 替换脚本的进程环境里不能再有这些变量，其余环境变量照旧
- 同一只鼠标被 2.4G 和蓝牙同时读到时只留一行，且是 2.4G 那行
- 诊断报告要写出 ASUS 控制接口和每次读取的结果

另外用一个批处理做了端到端验证：设好 `_PYI_*` 后走真实的替换脚本，新副本
收到的环境里没有这些变量。
