# BatteryTray 1.3.5

这一版修的是**更新**：点「立即更新」之后程序会直接消失，更新停在半路，
新版本也不会自己起来。

## 问题在哪

更新下载的时候，界面上的进度条是**从下载线程里直接画的**。

Tkinter（界面库）只允许拥有窗口的那个线程去动控件。从别的线程画进度条，
Windows 上不是报个错就算了，而是整个进程直接崩掉 —— 这次的日志里就是
`python313.dll` 里的访问冲突（`0xc0000005`）：

```
出错应用程序名称：BatteryTray.exe
出错模块名称：python313.dll
异常代码：0xc0000005
```

崩掉的是**正在下载更新的那一版**，所以现场是这样的：

- 托盘图标没了，程序整个退出
- 下载停在第一个 256KB 上，程序目录里留下一个下了一半的临时文件
- 因为没走到换文件那一步，硬盘上还是旧版本，但用户看到的是"更新把程序搞坏了"

## 怎么修的

- 进度和「正在重试」的提示不再从下载线程直接画，而是交给界面线程去更新。
  下载线程只负责下载和报数，界面线程负责画。
- 顺手把换文件那一步做结实了：
  - 下载完先确认**真的是个程序**（文件头是 `MZ`）才动手。以前这个检查只对
    `.exe` 结尾的文件生效，而更新时存的是 `BatteryTray.exe.new`，等于没检查，
    一个错误页面也能把主程序换掉。
  - 换文件失败（新文件不在、搬不过去）会把**旧版本放回原位**，不再留下一个
    「快捷方式指向不存在的文件」的现场。
  - 写批处理文件时不再多出回车符（`\r\r\n`），这种小毛病最爱的就是在别人的
    机器上才发作。
  - 等待旧进程退出的循环补上了上限，卡住的进程不会让更新脚本永远转下去。

## 验证

- `tools/test_update_restart.py`：用构建好的 `BatteryTray.exe` 完整走一遍
  「等旧进程退出 → 换文件 → 启动新版本」，现在三个步骤都通过。
- 另外用真实界面把整个更新流程跑了一遍（本地文件代替网络下载）：
  - 旧代码：进程以 `0xC0000005` 崩掉 —— 和用户遇到的一模一样
  - 新代码：窗口关闭、文件换好、新版本自己起来
- `verify_all.py` 273 项全过，新增 5 项，其中一项专门盯着
  「更新进度必须由界面线程处理」，另一项盯着安装包里的版本号不许掉队。
