# BatteryTray 1.3.3

这一版修的是「换了台电脑就什么都读不到」的问题。

## 为什么别的电脑上什么都看不到

### 1. 一个驱动出错，整个列表就空了（最主要的原因）

程序会去问五个驱动：Razer、罗技、若干厂商的 2.4G 接收器、XInput 和蓝牙。
其中前几个要通过 `hidapi` 直接访问 Windows 的 HID 子系统。

在有些电脑上，这一步会被系统拒绝 —— 进程权限不够、HID 子系统没就绪、
或者装了某些安全软件拦了 HID 设备的访问。这时候 `hid.enumerate()` 会抛异常，
而异常会一路冒泡到收集设备的那个函数，把整个设备列表变成空的。

程序之前把这个异常悄悄吞掉了，所以用户看到的只是「什么都没有」，
既没有设备，也没有错误提示 —— 完全无从查起。

**现在**：每个驱动都被单独询问。某一个驱动失败，其他驱动照常工作，
蓝牙设备照样能显示出来。同时失败的驱动会被记下来，写进状态文件里。

HID 子系统拒绝回答时，驱动们会把这个失败悄悄咽下去，好让其它设备
    20|继续显示 —— 但失败的原因会被记下来，一并写进状态文件。
所以现在既能读到设备，也知道到底哪里出了问题。

### 2. 蓝牙活动时间戳算错了 8 小时

Windows 给蓝牙设备节点记的「最后活动时间」用的是**本地时间**，
而其他时间戳用的是 UTC。程序之前一律按 UTC 处理，
在中国时区就差了 8 小时 —— 一个正在使用中的设备会被判定为
「两小时前就断开了」，于是电量被隐藏掉。

**现在**：活动时间戳按本地时间正确换算，判定结果和实际状态一致。

### 3. 判定「设备是否连着」只看了一个信号

Windows 对「设备在不在」有好几个记录，程序之前只用了其中一个，
而那个标志在手柄这类设备上**永远是 False**，哪怕手柄正在使用。

**现在**：综合判断 ——

- 蓝牙无线电（`BluetoothFindFirstDevice`）报告的链路状态最权威
- 设备节点的活动时间戳紧随设备
- 电量上报时间作为补充
- 注册表里的时间戳作为兜底

各信号的过期时间也按各自的更新频率分别设定
（活动 10 分钟、注册表 15 分钟、电量上报 6 小时），
不再用统一的 5 分钟 —— 手柄这种设备可能几小时才上报一次电量。

### 4. 默认不显示游戏手柄

新装的时候默认只显示鼠标和耳机，游戏手柄和键盘要手动去设置里勾选。
如果用户手上只有手柄，打开就是空的。

**现在**：四种外设默认全部显示，不需要的可以在设置里关掉。

### 5. 缺少 XInput 支持

插着 USB 线或者用无线适配器的手柄，Windows 把它暴露成 XInput 设备，
而不是蓝牙节点。蓝牙驱动完全读不到它。

**现在**：新增 XInput 驱动，覆盖插线和适配器两种情况。

## 诊断脚本

安装目录里多了 `check_batterytray.py`。用启动 BatteryTray 的同一个账号运行：

```
python check_batterytray.py
```

它会分别打印每个驱动读到了什么、HID 子系统的状态、蓝牙无线电的答案，
以及应用最终显示的设备。这样就能一眼看出是哪个环节出了问题。

程序自己的状态文件 `%APPDATA%\BatteryTray\status.txt` 现在也会写明
哪些驱动失败了、失败的原因是什么。

## 其他

- 蓝牙活动时间戳按本地时间正确换算，不再有时区偏差
- 每个驱动都被单独保护，一个驱动失败不会影响其他设备
- 默认显示游戏手柄和键盘
- 新增 XInput 驱动，支持 USB 和无线适配器连接的手柄
- 新增 `check_batterytray.py` 诊断脚本
